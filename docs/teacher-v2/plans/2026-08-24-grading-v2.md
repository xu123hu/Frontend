# Grading V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking. The product owner expressly chose inline continuation after the PRE-CODE GATE; do not wait for a second approval before Task 1.

**Goal:** Replace the Legacy /teacher/grading select-plus-form page with an evidence-driven, question-focused senior-high-school mathematics grading workstation that persists only explicit, audited teacher decisions.

**Architecture:** Add an additive backend GradingWorkspace projection and a separate persisted manual-review action; retain existing confirm_grade as the unique formal-score/mastery writer. Build a new V2 page tree whose components consume only the workspace adapter, then change the existing official route loader after contract, browser, screenshot and hard-similarity gates pass. Legacy TeacherGradingView.vue is never edited.

**Tech Stack:** FastAPI, SQLAlchemy async/PostgreSQL JSONB, Alembic, pytest/httpx; Vue 3 Composition API, Pinia, Vue Router, TypeScript, Vitest, Playwright, KaTeX; existing Vite mock middleware.

**Spec:** docs/teacher-v2/references/grading/RECONSTRUCTION_SPEC.md, docs/teacher-v2/references/grading/REFERENCE_EVIDENCE.md, docs/teacher-v2/references/grading/REFERENCE_SCREEN_MAP.md, docs/teacher-v2/references/grading/BACKEND_TO_V2_MAPPING.md

## Global Constraints

- This is reconstruction, not an incremental Legacy refactor: src/pages/teacher/TeacherGradingView.vue and its Legacy CSS remain untouched.
- The first V2 screenshot that preserves the Legacy top-select + generic-answer-panel + detached-side-score-form skeleton is a hard fail: delete the V2 page tree and reconstruct it from the Region A–E Screen Map rather than applying visual patches.
- The initial V2 shell contains only the grading workstation; do not create global Teacher OS navigation, a generic design system, cross-module providers, tokens or speculative shared components.
- Every visible product behaviour traces to the V2 evidence pack; grading’s GitHub evidence is the verified openwebwork/webwork2 clone and its license/source trace in REFERENCE_EVIDENCE.md.
- Inputs and browser validation use documented senior-high-school mathematics teaching material, not a fictional lesson or generic answer; source material is never redistributed as a product asset without a verified right.
- Components consume GradingWorkspace. Only the adapter talks to raw API shapes. Components never infer full marks/rubrics, calculate formal scores, or choose a stale next item from a local array.
- Existing POST /teacher/grading/{id}/confirm remains the unique score/mastery mutation and retains authorization, optimistic version, idempotency and TeacherAction audit semantics.
- Manual review is independent of automatic/OCR needs_review; review never changes SubmissionItem.score, teacher_final_score, mastery or suggestion confidence.
- V2 hides confidence percentages, raw workflow/type/debug strings and fabricated completion claims.
- Mock and real API contracts are isomorphic; any V2 required field is covered by backend, adapter and mock tests.
- Use isolated worktrees in the existing managed parent D:\codex-worktrees: frontend branch codex/teacher-v2-grading-frontend at D:\codex-worktrees\frontend-grading-v2; API branch codex/teacher-v2-grading-api at D:\codex-worktrees\math-arena-grading-v2. Original dirty user files remain in the original worktrees.
