# 真实教师验证计划（V3.4 二次备课共备桌 · Hero Flow A）

> 目的：把"该原型已具备进入真实教师任务测试条件"变成可执行、可证伪的下一步。
> 本计划本身遵守诚实边界：以下所有时间阈值都是**测试规则**，不是未经验证的行业标准；任何一项的效度都要靠实测数据建立。

## 1. 设计教师（第一位，持续参与）

- 找 **1 位正在带高二或高三数学**的教师作为设计合伙人，持续参与 2–4 周（每周至少 1 次真实使用 + 1 次复盘），不是一次性访谈对象。
- 要求其携带**真实材料**：去年同课的教案/PPT、在用教材（拍下所用页）、备课组共案、本班最近一次作业/测卷错情、明天的真实课表班级。
- 不做培训式演示：第一次接触即给任务，观察自然行为（找什么、点哪里、何时皱眉、何时想回 Word）。

## 2. 先记录原方法基线（同一教师）

在接触平台前，先观察并计时教师用**现有方法**（Word/PPT/教材/微信/浏览器）完成一次真实的"为明天某班二次备课"：

- 分段计时：找旧课与材料、读与对照、决定改动、写改动、找/选题、做提纲或 PPT、失败恢复（断电/找不到文件/改错版）。
- 记录切换次数（Word↔PPT↔浏览器↔微信）、重复录入次数、最终成果形态、完成后"敢不敢明天直接上课"。

## 3. 平台任务（与基线同构）

让教师用共备桌完成**同一件任务**：从去年《椭圆（或教师真实课题）》为明天的班完成二次备课，至少覆盖：

1. 从教案首页"继续已有工作"进入旧课；
2. 在来源桌翻旧课/演示教材页/共案，至少做 1 条批注、1 次引用到备课稿；
3. 改动至少 1 个核心问题或检查点，并写"本班调整理由"；
4. 对当前片段取用 ≤1 条资源候选的局部内容（或走"继续手写"）；
5. 对 1 条演示建议看 diff，做出接受或拒绝，并至少撤销 1 次；
6. 预览上课提纲与课件候选；
7. 教师自选时机刷新页面，确认能接着干。

## 4. 记录指标（净任务时间拆账）

对每个任务记录：**输入 + 等待 + 校对 + 修改 + 找资源 + 页面切换 + 格式转换 + 失败恢复** 的分项时间；同时记录：

- 修改次数与修改分布（哪些改动平台做不了、被迫回 Word/PPT 的时刻——**只要发生回退，该环节记为不通过**）；
- 对来源标注（演示教材页/未核验/演示班情）的理解复述（问"这个页码你信吗"）；
- 接受建议前是否真的读了 diff；撤销是否被使用；
- "是否敢明天拿去上课"（5 分制 + 追问原因）；
- 公式输入卡壳次数（数学输入台是否比手写快）。

## 5. 通过/不通过门槛（测试规则，非行业标准）

- 平台净任务时间 **≤ 教师原方法**，或超时部分被教师明确认可的下游价值抵消（教师自己说出"虽然慢点但是……值"）；
- **零回退**：核心改动、取题、写理由、提纲预览四件事不被迫回 Word/PPT；
- 刷新恢复 100% 成功；失败态（断网/服务失败模拟）下教师不丢内容且知道下一步；
- 教师能正确复述"演示教材页不是正版全文""演示建议需自己核验"——信任标注被读懂；
- 第二次使用（一周内）时，教师**主动使用**上次的续备资产（批注、理由块、引用）。

## 6. 扩样（设计教师通过后）

- 扩到 **6–10 位**不同教龄（0–3 / 4–10 / 10+ 年）、不同年级（高一/二/三）、不同数字熟练度的高中数学教师，每人 1 次任务 + 其中 3 人做第二次使用回访；
- 每人携带自己的真实旧课与班情，禁止使用我们的演示数据完成任务本身；
- 输出：逐人净时间对比、回退时刻清单、"愿意再次使用"意愿与原因。

## 7. 明确不验证/不宣称

- 不验证"AI 理解真实班情"（班情是教师自己写的演示备注）；
- 不验证导出与推送（课件候选是本地投影视图）；
- 不验证教材授权、题库供给、协作——这些是 IFC 待接入能力；
- 本计划通过后允许宣称的只有："Hero Flow A 在 N 名真实教师任务中通过/未通过，证据如下。"
