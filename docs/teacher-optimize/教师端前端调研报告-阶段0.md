### 2.2 三类归纳

- **人人有（必须有）**：学情/成绩可视化（9 家至少"弱"）；作业发布收发（6/9）；批改进度感知（智学网"已阅17/46"式进度，截图 01b）——本项目的队列进度、insights 卡属底线项，不能缺席。
- **部分有（差异化机会）**：①**自动批改**——国内仅讯飞/好分数/菁优有，且强绑定校方网阅场景；"个人教师日常作业 AI 批改"是空白，本项目 V2 工作台（建议+人工确认+乐观锁）正好落位；②**AI 讲解/生成**——国内产品全是"弱"（学科网 AI 组卷刚起步，截图 07），海外 MagicSchool/Khanmigo 已验证"教师 AI 工具箱"模式（$12.99/月有人付费）；③组卷双寡头（学科网/菁优）**均无批改与学情回流**。
- **没人做（谨慎，但本项目有契约优势）**：**"组卷→布置→批改→学情→再教学"闭环——9 家无一家打通**（组卷系不批、批改系不组）。这正是本项目黄金路径 L3→L4→L5 与 PRODUCT_VISION 的核心命题；因前后端契约已在（artifacts/assignments/grading/insights 全链端点稳定承诺，§7.1），非伪需求，**应作为唯一差异化主轴宣发与打磨**。次谨慎项：单科纵深"AI 给教师讲题"（教师需要的可能是"讲评课件"而非对话讲题——Butler/讲评设计时引用此结论）。

### 2.3 目标用户最集中的 5 大吐槽（全部带来源，设计反模式清单）

1. **查分/错题收费圈钱**：好分数 1.57 分"看成绩要充 VIP"（apps.apple.com/cn/app/id1037944189）、365 元/年提前看成绩事件（m.huxiu.com/moment/1009726.html）、菁优"VIP 60 元仅 20 次下载"（apps.apple.com/cn/app/id862280922）→ **启示：核心教学动作（批改/学情）绝不设付费墙式功能残缺**。
2. **广告泛滥**：班级小管家 3.2 分集中吐槽（apps.apple.com/cn/app/id1524125516）→ 教师端零广告。
3. **稳定性差**：好分数阅卷故障致退费（m.huxiu.com/moment/1009726.html）、菁优导出文件 WPS 打不开数月不修 → **启示：导出/下载链路必须接 401 刷新与失败重试（对应 §5 N3），降级要明示**。
4. **更新后交互退步**：智学网教师端 3.24 分"更新后打分不显示分数、别更新了"（apps.apple.com/cn/app/id1064856546）→ **启示：V1/V2 收敛必须保能力不缩水（对应资产表 #8 的收敛纪律）**。
5. **移动端适配差/效率低**：智学网"切图小看不清字"、希沃"iPad 无适配"（apps.apple.com/cn/app/id1433177930）、Classroom"通知坏一年多"（2.04 分，apps.apple.com/us/app/id924620788）→ **启示：PC 优先但信息密度与可读性对标智学网差评反向设计**。

## 3. 用户画像卡（底稿核验修订版）

> 底稿来源：优化提示词 §1.1（画像 A/B）。核验证据：诊断报告实测记录、`docs/teacher-refactor/BUSINESS_OBJECTS.md` 统一 Demo 数据世界、竞品实拍（§1）与文字调研（§2）。修订处加粗标注。

### 画像 A · 批改减负型（核验通过，证据补强）

- **基本属性**：王老师，38 岁，教龄 14 年，带 2 个班约 110 人（数据世界锚点：高二(3)班 46 人），办公室 PC（1600×900 上下），晚自习批改 2~3 小时/天。
- **使用场景**：晚自习/课间，PC 端批量处理当天作业；手机只看结果通知。
- **第一分钟想干什么**：打开产品直接看到"今天要批多少份、哪些学生要关注"（Grading V2 队列 + Today 待批数；GOLDEN_PATH GP-9 队列深链）。
- **最怕什么**：①AI 批改不可信（诊断报告 G-03/G-05：原始调试信息直出、置信度 40% 无解释）；②误点丢数据（V2 用乐观锁 version + 幂等键 + confirm 双写防护——**现有代码已是差异化卖点，竞品实拍未见同类保障**）；③看不见题干和学生（G-01/G-02，后端修复中）。
- **现有替代方案**：手改纸质作业；智学网移动阅卷（截图 01b：手写原卷+给分键盘，"第17题（已阅17/46）"——**逐题滚动+进度感知是竞品已验证的形态**，与本项目 V2 同构）。
- **期望**：逐题确认流畅（"确认下一份"一键循环）、批量确认、复看机制不被打断。
- **对应链路**：L4（核心）、L1。

### 画像 B · 出题质量焦虑型（核验通过，修订"期望"栏）

- **基本属性**：李老师，26 岁，教龄 3 年，带 1 个班 46 人，备课时间碎片化（办公室 PC + 家里笔记本）。
- **使用场景**：备课时按课题出练习/组卷；课前 10 分钟出当堂检测。
- **第一分钟想干什么**：输入课题（如"函数的单调性"）→ 得到一套可信、难度结构合理的练习。
- **最怕什么**：①**文不对题**（诊断报告 A-01 实测：选"函数的单调性"出的 8 题全是解方程题——被学生问倒的社交风险）；②题目模板重复（A-02）；③超纲/难度失真（A-04 挑战题 0 命中）。
- **现有替代方案**：组卷网/学科网（截图 03）：**章节选题/知识点选题/试卷选题/智能组卷四种方式**——教师要的是**可控的选题**（看得见题、能换题），不是一键黑盒；学科网已上 AI 组卷（截图 07）。**修订**：底稿假设"一键生成即可"，竞品证据表明必须给"逐题可见、可换、可锁"的控制感（与 R06 每题四件套：编辑/换一题/重新生成/锁定 一致）。
- **对应链路**：L3（核心）、L2。

### 画像 C · 讲评驱动型（新增提案，依据产品愿景与后端能力现状）

- **基本属性**：同 A/B，不单指某类人，而是**教学循环的第三段**：批改完→下节课要讲什么→讲完有没有效果。
- **第一分钟想干什么**：批改完成后立刻知道"最值得讲的 3 题是哪几道、错因是什么、怎么干预"。
- **最怕什么**：洞察是空话/假数字（诊断报告 T-02/T-04、CL-02：`count=5` 原始字段直出、无真实教学建议；Today 硬编码"17/46"）。
- **证据**：`docs/teacher-refactor/PRODUCT_VISION.md` 核心命题"谁能把一次学生错误最快变成老师下节课的教学行动并验证效果"；R06 主线即闭环右半环；竞品空白——**实测 8 个竞品无一提供"错题→讲评行动→效果验证（54%→81%）"闭环**（差异化机会）。
- **对应链路**：L5（核心）、L1、L4 讲评面板。
- **风险**：该画像高度依赖后端 insights 质量（insights.py 修复中），前端文案模板引擎（§3.1）是本期前端可独立交付的部分。

### 4.2 选型结论：以 pure-admin-thin（vue-pure-admin 精简版）为主蓝本

三候选对比（GitHub API 2026-09-01 数据）：

| 项目 | star | 最近推送 | 形态 | 对本项目的适配成本 |
|---|---|---|---|---|
| vue-vben-admin v5.7 | 33,327 | 2026-08-31 | pnpm+turbo monorepo | 高（workspace/Node22/全量 vue-tsc；迭代被社区批评引入回归，如 issue #8032、#8122） |
| soybean-admin v2.2 | 14,922 | 2026-08-13 | pnpm workspace + elegant-router | 高（TS strict 强绑定、文件路由与 TS 耦合） |
| **vue-pure-admin v7 / pure-admin-thin v6.2** | 20,580 | 2026-08-23 | **单仓库传统分层** | **最低（src/api 平铺 + utils/http 单例 + store/modules，可局部搬入）** |

**三条理由**：
1. **适配成本最低**：pure-admin-thin 为单仓库（本机克隆已验证：`src/api` 平铺 ts、`src/store/modules`、`src/utils/http`、`src/router/modules`、`src/views`），与本项目"JS 入口/路由 + TS API/stores"的存量结构一一对应，只需局部借鉴请求层与目录规范，不必整套引入；vben5/soybean 的 monorepo + 全量类型链对 8 页规模是纯负担。
2. **请求层规范恰到好处**：其 `utils/http` 的 token 过期前置刷新（队列+锁重放+白名单）模式，可对照强化本项目 `client.js:78-88` 的 401 刷新重试；业务码提示留白，正好按我方 `{code,message,data,request_id}` 信封补齐。
3. **活跃且问题已沉淀**：2026-08-23 仍在推送，MIT；高频历史 issue 多已关闭。

**局部借鉴（非整套硬搬）**：vben 的统一错误提示拦截器与 base/业务双实例拆分思路；soybean 的 flat request 泛型风格供 TS API 层参考。
**借鉴纪律**：只借鉴分层思想与请求模式，禁止搬运 UI 组件与权限体系（UI 基准仍用既有克隆/竞品截图体系）。
