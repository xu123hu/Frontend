# PRODUCT_VISION — 智学数研教师端

> 状态：**ACCEPTED**（2026-08-23，Product Architect）
> 冲突优先级：本文档为产品方向最高 SSOT，仅次于 Shared Project Constitution。

---

## 1. 一句话定位

**智学数研教师端是一个"数学教学管家操作系统"（Teacher OS），不是一个带 AI 按钮的后台。**

它回答的唯一核心问题是：

> **"学生昨天哪里不会，老师今天和下一节课应该为此做什么？"**

## 2. 我们不是什么

| 不是 | 为什么 |
|---|---|
| ChatGPT 套壳 | AI 不通过万能聊天框工作；AI 以具体业务动作进入教师任务 |
| Dashboard 模板 | 首页不是数据大屏，是行动中心（Action Center） |
| 功能陈列页 | 模块不按"系统能力"组织，按"教师任务"组织 |
| LMS 复制品 | 不做 Canvas/Moodle 的全量复杂度；只做高中数学教学闭环 |
| 竞品换皮 | 借鉴成熟产品的任务结构/交互模型/信息层级，不复制品牌与代码 |

## 3. 差异化命题（唯一护城河）

市面上所有教师 AI 产品都在比"我有多少 AI 功能"（AI 备课、AI PPT、AI 出题……）。
我们的比赛是另一条：

> **谁能把一次学生错误，最快、最自然地变成老师下一节课的一次有效教学行动，并验证这次行动有没有用。**

即这条链（v2.1 SSOT 已定义、也是本项目验收主线）：

```
学生昨天哪里不会
  → AI 今天提醒老师（带证据）
  → 老师一键把它带进明天的课（AI 只改最相关的环节）
  → 自动生成当堂检查题（经数学验证）
  → 课堂收回答案
  → 作业继续验证
  → 系统告诉老师"54% → 81%，这次补讲有效"
```

**任何模块脱离这条闭环独立存在，都是失败。**

## 4. 目标用户与核心 Jobs To Be Done

**用户**：普通高中数学教师（示范画像：李老师，高二数学，带高二（3）班 46 人；技术素养普通；每天备课 + 授课 + 批改 + 学情合计工作时间有限）。

| # | Teacher Job | 对应模块 |
|---|---|---|
| J1 | "我今天/明天最该先做什么？" | Today |
| J2 | "沿用已有材料，把三班容易错的地方补进这节课，其他不动" | Lesson Planning |
| J3 | "形成能直接上课的产物（PPT/练习/板书）" | Lesson Artifact |
| J4 | "出一份 20 分钟小测，每题我都过目，答案可信" | Assignment Builder |
| J5 | "连续批 40 份卷子不能累死；AI 只帮我定位问题，分数权在我" | Grading |
| J6 | "上课时我知道学生此刻会不会，能立刻发题/看分布/推变式" | Classroom |
| J7 | "哪个班/哪些知识点/哪些学生需要我干预？下一步做什么？" | Classes / Analytics |
| J8 | "我上次用的那个素材，能直接进明天的课" | Resources |

## 5. 产品级不可协商原则

1. **任务优先**：页面围绕教师任务组织，不围绕系统能力组织。
2. **上下文连续**：页面永远让教师知道"我正在操作哪个班/哪门课/哪节课/哪份作业/哪个学生"。
3. **AI 即业务动作**：AI 以具体、有目标页面的动作出现（加入下节课/出巩固题/换一题/给另一种讲法），不是自由 Prompt。
4. **Artifact 而非 Chat Message**：AI 输出必须落成可编辑业务对象（lesson/slide/quiz/grading artifact），带 artifact_id，可 Preview/Edit/Regenerate/Undo。
5. **Confirmation Gate**：AI 结果一律 draft；发布、成绩、正式课件必须教师显式确认后进入正式状态。AI 永远只是建议。
6. **证据链**：每条学情洞察必须"发生了什么 → 证据 → 为什么现在 → 一键动作"，100% 可查依据。
7. **无工程泄露**：UI 禁止出现 confidence / type=rule / workflow / raw JSON / 内部枚举 / 秒数有效期等工程表达。
8. **无原生调试交互**：禁止 window.prompt / window.alert / alert() / prompt() / console TODO / dead button / 假 toast。
9. **状态完整**：每页必须有 loading / empty / error；AI 流程另有 generating / failed / cancelled / needs_confirmation。
10. **AI 不可用时业务仍可走**：能力网关降级（local fallback）后基本流程不中断，禁止把降级状态当成产品语义展示给教师。
11. **URL 表达业务对象**：当前操作对象进 URL（批改的 submission_item_id、备课的 lesson_id 等），刷新/分享/直接打开都能回到同一上下文。
12. **统一数据世界**：全站引用同一份固定 Demo 事实（李老师 / 高二（3）班 46 人 / 《导数与函数单调性》/ a=0 边界 17 人失分 / 21 份待批 / 7 人视频未完成），页面之间数字一致。

## 6. 成功标准（最终判断）

不看"页面是不是变漂亮了"，看：

> **真实高中数学教师第一次打开系统，能否理解它，并顺畅完成：备课 → 授课 → 作业 → 批改 → 学情分析 → 下一次教学干预。**

量化验收锚点（详见 ACCEPTANCE.md）：

- Golden Path 首页→备课→出题→发布→批改→学情→回流，浏览器一次性真实走通，任一步失败即整条失败。
- 每页通过 10 条 UX Gate（10 秒可理解 / 首屏有主动作 / 无 Prompt 可完成主任务 / 上下文可见 / AI 有依据 / AI 变 Artifact / 无工程泄露 / 空态有用 / 最终权在老师 / 闭环有下一步）。
- 任何页面出现下述之一即验收失败：dead button、原生弹窗、内部字段上屏、AI 结果直接写正式数据、批改页显示置信度。

## 7. 范围边界（本轮明确不做）

- 不做移动端优先（Desktop 1440×900 优先，1366×768 可用）。
- 不做实时课堂 websocket 全联通（Demo 用确定性 session mock，但状态机与 API contract 必须真实）。
- 不做生产级权限系统 / SIS 对接（后端 M3 verified teacher + class scope 已够）。
- 不做大规模 RAG / OCR / 真 PPT 渲染服务（保留 capability 接口与确定性降级）。
- 不做班级管理深度 CRUD（成熟稳定即可，不 AI 化）。
